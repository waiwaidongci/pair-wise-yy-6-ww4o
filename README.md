# 墨锭磨后洗养与入库核验台

由「墨锭试磨室」扩展而来，覆盖试磨后的洗养、换人复核、入库核验与领用管控。

运行：

```bash
npm start
```

访问 `http://localhost:3037`。数据保存在 `data/ink-stick-testing.json`。

## 模块划分（请求 / 判定 / 存储各自独立）

- `server.js` — 请求模块：HTTP 路由、请求体解析、响应与错误码，不含业务判定。
- `rules.js` — 判定模块：洗养、复核、入库、领用、档案变更的全部业务规则，以及统计与单锭履历聚合；不接触文件系统。
- `store.js` — 存储模块：JSON 文件读写与旧数据结构迁移（幂等）。
- `view.js` — 页面模块：列表、表单、统计与履历弹窗，数据全部来自接口。

## 业务规则

- 状态流转：`待试磨 → 已试磨 → 待复核 → 已入库`；洗养不合格进入 `待复洗`。
- **待复洗暂停领用**：对该状态墨锭的领用请求返回 409，页面领用按钮禁用。
- 洗养单记录：换水次数、洗液浑浊度（清澈/微浑/浑浊）、擦干程度（干透/表面微湿/边角余湿）、养护人。
  换水不足 3 次，或擦干程度不是「干透」（仍见余湿），即判 `待复洗`；合格则转 `待复核`。待复洗后可再提交洗养单。
- 复核须**换人**（初检人与复检人不同人），两次检查级别（一/二/三级）差不超过 1 级才准入库，否则单据不收、状态不变。
- 烟料来源或胶料比例变更后：原入库结论失效（旧复核单保留并标记失效原因、时间），墨锭退回 `待复核`，且**不计入可入库数量**；重新复核产生新单。仅改存放位置/年限不失效。
- 「可入库」只统计持有有效入库结论（`activeReviewId` 指向未失效复核单）的墨锭。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/items` | 列表（含末次洗养、有效入库结论、暂停领用标志） |
| POST | `/api/items` | 建档（仅允许 待试磨/已试磨） |
| PATCH | `/api/items/:id` | 档案变更；烟料/胶比变更触发结论失效 |
| POST | `/api/items/:id/tests` | 试磨记录 |
| POST | `/api/items/:id/washes` | 洗养单（判定 待复核/待复洗） |
| POST | `/api/items/:id/reviews` | 复核入库单（换人 + 级别差 ≤1） |
| POST | `/api/items/:id/requisitions` | 领用登记（待复洗返回 409） |
| GET | `/api/items/:id/history` | 单锭履历（操作/试磨/洗养/复核/领用合并时间线） |
| GET | `/api/stats` | 各状态、可入库、暂停领用计数 |

页面列表、统计卡片与单锭履历共用同一份存储数据（`summarize` / `computeStats` / `buildHistory` 均在判定模块内派生），刷新重载后互相一致。
