# 磨后洗养与入库核验台

由「墨锭试磨室」扩展而来，覆盖墨锭试磨后的洗养、复洗、换人复核入库与领用全流程。

## 运行

```bash
npm start
```

访问 `http://localhost:3037`。数据保存在 `data/ink-stick-testing.json`，旧版试磨室数据首次启动自动迁移（旧的「已试磨 / 重点观察」转入「待洗养」，历史试磨日志保留）。可用环境变量 `PORT`、`INK_DB_PATH` 覆盖端口与数据文件位置。

## 业务规则

- 流程：待试磨 →（试磨）→ 待洗养 →（洗养单）→ 待核验 →（换人复核）→ 已入库。
- 洗养单记录换水次数、洗液浑浊度、擦干程度、养护人；换水不足（少于 3 次）或擦干仍见余湿，进入「待复洗」。
- 「待复洗」墨锭暂停领用；复洗通过后回到待核验。
- 入库核验须换人复核（复核人 ≠ 初检人），两次检查级别差不超过一级才准入库；驳回留单并维持当前状态。
- 已入库墨锭可领用、归还后恢复入库状态。
- 烟料来源或胶料比例变更后，原入库结论失效：旧洗养单与核验单全部保留（标记作废原因），墨锭转「结论失效」须重新核验，且**不计入可入库数量**。

## 模块划分

| 文件 | 职责 |
| --- | --- |
| `server.js` | HTTP 入口，仅做路由分发 |
| `src/api.js` | 请求模块：解析请求/响应、错误码，调用判定与存储 |
| `src/rules.js` | 判定模块：全部业务规则（纯函数，不接触 HTTP 与文件） |
| `src/storage.js` | 存储模块：JSON 文件读写、种子数据、旧结构迁移 |
| `src/page.js` | 页面模块：列表、统计、单锭履历共用同一组接口，操作后整体重载保持一致 |

主要接口：`GET /api/meta`、`GET/POST /api/items`、`GET/PATCH /api/items/:id`、
`POST /api/items/:id/tests|wash-sheets|verifications|requisition`、`DELETE .../requisition`、`GET /api/stats`。
